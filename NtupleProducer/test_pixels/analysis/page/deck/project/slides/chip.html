II · Idea A: pixels in L1 · Readout chip

11 / 16 (+11 backup)

How the pixel readout chip handles one crossing. Every group of pixels stores a time stamp with its hits. The chip has one programmed latency, set to match the L1 decision time. When a hit reaches that age, the chip checks whether a trigger came in for that crossing: if yes, the hits are marked for readout, if not, they are erased. To use pixels in the L1 decision we would need some hits around 1 to 5 microseconds, while still keeping all hits until the normal accept at 12.5 microseconds, for every crossing. The chip has no such second path. The RD53B design has a “two-level” mode built for an L0/L1 trigger scheme that ATLAS once considered: a first trigger marks crossings and a later command selects them, but readout still happens after a second fixed delay, the same for all crossings, and it would need a first-level trigger for every crossing CMS might accept. Neither experiment’s Phase-2 baseline uses two hardware trigger levels. The production CMS chip (CROCv2, RD53C) uses the same single programmable latency; the RD53C manual itself was not checked, so this should be confirmed with the chip experts.
